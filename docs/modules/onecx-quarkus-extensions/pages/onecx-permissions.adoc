=== Installation

If you want to use this extension, you need to add the `org.tkit.onecx.quarkus:onecx-permission` extension first to your build file.

For instance, with Maven, add the following dependency to your POM file:

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>org.tkit.onecx.quarkus</groupId>
    <artifactId>onecx-permission</artifactId>
    <version>{project-version}</version>
</dependency>
----

=== Usage

1. First you need to add the maven dependency shown at the top
2. Then you can use @PermissionsAllowed annotation

[source,java]
----
    @GET
    @Path("write")
    @PermissionsAllowed(value = "onecx:resource#action")
    public Response adminWrite() {
        return Response.ok("OK").build();
    }
----

=== Troubleshooting 403

When a request is rejected because the user is missing a OneCX permission, the extension logs a warning with the required permissions:

[source,text]
----
WARN [org.tkit.onecx.quarkus.permission.PermissionDeniedLogger] OneCX permission denied, request GET /test/write, required [onecx:resource1#admin-write], granted 2 permission(s)
----

If the permissions could not be loaded from the `onecx-permission-svc`, the error is logged first and the warning ends with `permissions could not be loaded from onecx-permission-svc`:

[source,text]
----
WARN [org.tkit.onecx.quarkus.permission.service.PermissionClientService] Failed to load permissions from onecx-permission-svc, product test1, application app-id, error HTTP 500
----

To see the list of permissions granted to the user, enable `DEBUG` level for the permission logger:

[source,properties]
----
quarkus.log.category."org.tkit.onecx.quarkus.permission".level=DEBUG
----

The access token is never logged.

NOTE: `@PermissionsAllowed` values must use the `onecx:resource#action` format; the prefix is configured by `onecx.permissions.name`.
